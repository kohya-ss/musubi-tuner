# DLSS-NR Trainable Forward Alignment, 2026-09-24

## Acceptance Scope

The user chose a trainable forward with close visual/pixel agreement over a
bit-exact, potentially more expensive native implementation. This update keeps
canonical FP32 master weights and automatic differentiation. It does not route
training through the DLL or add a native runtime dependency.

The existing suggested display thresholds remain unchanged: MAE <= 1/255,
PSNR >= 45 dB, P99 absolute error <= 4/255, on each fixed case. Raw-head,
preclamp, temporal and export validation are separate requirements.

**Result:** a large reduction in image disagreement, but not full acceptance.
9 of 19 image/control cases meet all three display thresholds. One is the
caller-prefilled zero-intensity bypass, so 8 of 18 nontrivial cases pass.
No successful forward-validation report was produced; the training gate was
unchanged at the time of this experiment. The current [training contract](dlssnr.md#训练输入与验证证据)
allows training without a report, but does not change these acceptance results.

## Actual Parameter Audit

The local D3D12 bridge was instrumented with a transparent NGX parameter wrapper:
each call is forwarded to the original parameter object and the DLL's actual
Get type/result is recorded. Reference DLL identity and screenshot provenance
are unchanged from [the first experiment](dlssnr_forward_experiment_2026-09-24.md).

Observed successful reads for the explicit baseline:

| Parameter | DLL Getter | Explicit Value |
| --- | --- | --- |
| Style | uint | 0 |
| Intensity | float | 1 |
| LocalToneStrength | float | 1 |
| LocalStructureStrength | float | 1 |
| SkinStructureStrength | float | -1 |
| UseAutoMask | int | 1 |
| Hint.Render.Preset | int | 3 |
| Reset | int | 1 |

When all artistic controls and the preset are omitted, their getters return
`BAD00010` (unset). On all four images the result is bit-identical to the
explicit tuple `style=0, intensity=1, tone=1, structure=1, skin=-1,
auto_mask=false, preset=3`. This demonstrates output-equivalent defaults for
these cases; it does not prove an internal default preset of 3, since preset
values can be output-inert.

The auto-mask difference is real, but it does not explain the original major
mismatch: both sides of the previous comparison explicitly used auto-mask=true.
The active NGX getters also rule out an assumed double/float ABI mismatch in
these ordinary parameters; a separate runtime-callback ABI is not interchangeable
with the ordinary NGX Get interface.

Logs and exact comparisons: `references/dlssnr_alignment_20260924/` contains
`explicit_params.log`, `implicit_params.log`, `no_auto_params.log` and
`defaults_audit.json`. All four omitted-vs-explicit-auto-mask-false comparisons
have zero error.

## Confirmed Corrections

1. Ordinary SiLU was not the shipped activation. Its cubic replacement uses
   `b=clamp(x,-4,4)` and
   `x * (b * (-0.055908203125 * abs(b) + 0.447265625) + 0.89453125)`.
   Only the polynomial argument is clamped; the positive output tail is not.
   Replacing this alone changed face MAE from 0.02936 to 0.00899. All dense,
   expert and split-512 FFNs now use the cubic with half publications.
2. Activation publication now rounds through half before E4M3. Residual values
   that the 32-channel blocks retain in raw half are kept separately, including
   the input adapter, decoder-32 entry and final full-resolution merge.
3. Window and global attention have their respective clamped exponential
   functions and half reduction order. ViT constants use the actual half values
   `0.08953857421875` and `1.708984375`, not their wider source spellings.
4. Cosine norms use half reductions, half learned scales and the ViT's separate
   sqrt(32) multiply. Defined zero rows return zero without nonfinite backward;
   arbitrary NaNs are not silently replaced by zeros.
5. Global attention publishes unnormalized E4 exponential weights, normalizes
   after the value accumulation, and explicitly subtracts the padded-token
   denominator contribution. Window reduction follows physical 4x4-tiled key
   order, rather than treating a float softmax as equivalent.
6. Pooling and skip merges retain their respective half/E4 publication points.

Primary implementation reference:
[OpenDLSS-NR numerics, commit 9d08f418](https://github.com/maanHimself/OpenDLSS-NR/blob/9d08f4184bbcb9d858e2fb7a7834ec0837a9d2f1/docs/numerics.md).
Scalar regression constants were independently evaluated using that repository's
browser CPU reference, not generated by the new production functions.

## Gradient and Compatibility Contract

- Matrix accumulation remains FP32; weights remain FP32 and are not requantized
  after optimizer updates. This is activation fake quantization, not an FP8-base
  training option or a native-export guarantee.
- Half/E4 rounding uses identity surrogate gradients. E4 saturation uses the
  clamp's zero derivative outside [-448, 448]. Gradients are not cast through
  float8 on the backward path.
- The exponential's derivative follows the continuous piecewise-linear mantissa
  approximation with the same clamp; integer bitcasts are not differentiated.
- FP32 accumulators and post-matmul residual adds still differ from native F13/F24,
  residual-seeded accumulators and split-K ordering. Simple 16/32-element half
  chunking was tested and was not a consistent improvement, so it was not shipped.
- A local Triton 3.2 FP8/half-accumulator prototype failed code generation and was
  not integrated. No extra packages or compiler/runtime dependencies were added.
- `SURROGATE_FLAGS.operators_version=2` records these choices. `arithmetic.py`
  participates in implementation identity, invalidating incompatible old resume
  states and validation reports. Existing canonical weight files can be loaded;
  old optimizer/RNG state is not an exact resume across this numerical change.
- Main inference still returns pre-display proxy RGB. The comparison harness
  separately applies the audited style/intensity composition. This update does
  not silently apply display grading to training targets or recurrent history.

## Measured Results

Same four full-frame 960x540 inputs, explicit controls, seed=0 in our backend,
native reset=1, and the same external display composition as the first run.
The DLL's hidden seed was not captured; native reset repeats remain deterministic.

| Default-Style Image | Previous MAE | Current MAE | Current PSNR | Current P99 |
| --- | ---: | ---: | ---: | ---: |
| Cyberpunk vehicle | 0.036306 | 0.003845 | 44.76 dB | 0.020020 |
| Witcher face | 0.029360 | 0.002616 | 47.84 dB | 0.015885 |
| Witcher landscape | 0.042008 | 0.005198 | 42.99 dB | 0.022705 |
| KCD II village | 0.034926 | 0.004168 | 44.84 dB | 0.018066 |

Default-style MAE is reduced by approximately 88-91%. The three-metric gate is
conjunctive: even the face above narrowly exceeds the P99 bound 4/255, so it is
not counted as passing. Natural/Cinematic, tone/structure, skin/auto-mask and
intensity results are all retained in `half_e4/metrics.json`; failures are not
removed from the matrix. Identity-at-zero is not neural parity evidence.

The same folder contains `.npz` files with raw head, preclamp, rendered proxy and
display arrays, and `comparison_default.jpg`, `comparison_natural.jpg`,
`comparison_cinematic.jpg`. Columns are input, local DLL, previous forward and
current trainable forward. Internal DLL boundaries are still unavailable, so
remaining errors cannot yet be assigned to a particular layer.

## Verification

Added 13 numerical tests, including independent scalar activation/exponential
values, half-before-E4 double rounding, non-quantized gradients, all FFN families,
attention value publication and finite zero-row backward. Tests were first run
failing against the missing/old behavior, then passed after the corrections.

The old random LoRA unit fixture underflowed through six E4 resolution levels.
Its input adapter and down-transition initialization were given a nonzero
bottleneck; the assertions were not weakened. The pretrained-weight CUDA test
separately requires finite, nonzero gradients in all 32 ViT adapters.

```powershell
$env:PYTHONPATH = (Join-Path $PWD 'src')
$env:OMP_NUM_THREADS = '4'
$env:MKL_NUM_THREADS = '4'
$env:DLSSNR_RUN_CUDA_SMOKE = '1'
python -m pytest -q --tb=short
```

Result: **172 passed**, no skips, 310.18 seconds. Focused Ruff checks also passed.
Real-weight CUDA tests completed a full update and a LoRA update; the frozen base
was unchanged, and merged/unmerged raw-head comparison passed its unchanged
tolerance. Observed peak CUDA allocation for the small padded smoke case was
6222.5 MiB full and 3843.3 MiB LoRA; these are not real-resolution training budgets.
